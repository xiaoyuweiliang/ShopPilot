# 基于 RAG 的多模态电商智能导购 AI Agent

## 一、项目概述

本项目基于原始 PRD，采用 **React Web 前端 + Node.js 后端 + RAG + 多模态
AI Agent** 的技术路线，实现一个面向电商场景的智能导购系统。

项目目标是将传统电商中的"信息展示"升级为"智能决策"，通过自然语言、多模态输入、RAG
商品检索、多轮对话和 Agent 工具调用，帮助用户完成：

> 需求表达 → AI 理解 → 商品检索 → 个性化推荐 → 商品对比 → 加入购物车 →
> 模拟下单

本项目只实现 **Web 页面**，不开发 iOS / Android 原生 App。

# ① 需求理解

## 1.1 核心业务目标

系统需要解决传统电商导购中的以下问题：

-   用户需要主动搜索和筛选商品
-   关键词搜索难以理解复杂自然语言需求
-   用户无法快速完成多个商品之间的比较
-   商品信息与用户真实使用场景之间缺少关联
-   用户从"浏览商品"到"做出购买决策"的路径较长

因此系统引入 AI Agent，使用户可以直接用自然语言表达需求。

例如：

> 我想买一个 300 元以内、适合跑步使用的蓝牙耳机。

系统自动理解：

``` json
{
  "category": "耳机",
  "scene": "跑步",
  "maxPrice": 300
}
```

然后结合商品数据库和向量数据库进行检索，最终由大模型生成推荐结果。

# ② 需求澄清 / 边界确认

## 2.1 MVP 必做功能

### 1. AI 对话

支持用户通过自然语言描述购买需求。

示例：

> 我想买一个 200 元以内的蓝牙耳机。

系统返回：

-   商品名称
-   商品图片
-   商品价格
-   商品评分
-   商品核心参数
-   AI 推荐理由
-   查看详情
-   加入购物车

------------------------------------------------------------------------

### 2. RAG 商品检索

根据用户自然语言需求，从商品数据中检索相关商品。

核心流程：

``` text
用户问题
 ↓
意图识别
 ↓
结构化条件
 ↓
向量检索
 ↓
结构化过滤
 ↓
商品排序
 ↓
LLM 推荐
```

------------------------------------------------------------------------

### 3. 多轮对话

支持上下文连续理解。

示例：

``` text
用户：推荐一个耳机

AI：为你推荐以下几款……

用户：我主要跑步用

AI：如果主要跑步，我更推荐……

用户：预算 300 以内

AI：结合你刚才的需求，我建议……
```

系统需要保存 conversation 和 message 数据。

------------------------------------------------------------------------

### 4. 商品详情

路由：

``` text
/product/:id
```

页面展示：

-   商品图片
-   商品名称
-   商品价格
-   商品品牌
-   商品评分
-   商品描述
-   商品规格
-   AI 推荐理由
-   加入购物车

------------------------------------------------------------------------

### 5. 商品对比

支持用户选择 2～3 个商品进行对比。

对比维度包括：

-   价格
-   重量
-   续航
-   防水
-   评分
-   商品核心参数

同时由 AI 给出最终建议。

------------------------------------------------------------------------

### 6. 购物车

支持：

-   加入购物车
-   修改数量
-   删除商品
-   计算总价
-   确认订单

------------------------------------------------------------------------

### 7. 模拟订单

不接入真实支付。

流程：

``` text
购物车
 ↓
确认订单
 ↓
订单商品
 ↓
商品数量
 ↓
总价
 ↓
模拟提交订单
```

# ⑤ RAG 技术方案

## 5.1 商品数据处理

商品数据示例：

``` json
{
  "name": "XX 降噪蓝牙耳机",
  "category": "耳机",
  "price": 299,
  "description": "适合运动使用，支持主动降噪",
  "features": [
    "主动降噪",
    "IPX5 防水",
    "30 小时续航"
  ]
}
```

转换为可检索文本：

``` text
商品名称：XX 降噪蓝牙耳机

分类：耳机

价格：299 元

描述：
适合运动使用，支持主动降噪。

特点：
主动降噪
IPX5 防水
30 小时续航
```

然后进行 Embedding：

``` text
商品文本
 ↓
Embedding Model
 ↓
向量
 ↓
Qdrant
```

------------------------------------------------------------------------

## 5.2 用户检索

用户：

> 我想买一个跑步的时候戴的耳机，预算 300 以内。

首先进行意图识别：

``` json
{
  "category": "耳机",
  "scene": "跑步",
  "maxPrice": 300
}
```

然后进行混合检索：

``` text
结构化过滤
    +
向量相似度
    +
商品评分
    +
场景匹配
    ↓
最终排序
```

可以采用：

``` text
Score =
0.5 × semanticScore
+
0.2 × priceScore
+
0.2 × sceneScore
+
0.1 × ratingScore
```

# ⑥ Agent 设计

## 6.1 Agent 核心原则

不建议让 LLM 直接执行 SQL：

``` text
LLM
 ↓
SQL
 ↓
Database
```

推荐使用 Tool / Function：

``` text
LLM
 ↓
Agent Tool
 ↓
ProductService
 ↓
Database
```

------------------------------------------------------------------------

## 6.2 Agent Tools

第一阶段实现：

``` text
search_products
get_product_detail
compare_products
add_to_cart
get_cart
```

### search_products

``` json
{
  "name": "search_products",
  "description": "根据用户需求搜索商品",
  "parameters": {
    "keyword": "string",
    "category": "string",
    "maxPrice": "number",
    "scene": "string"
  }
}
```

### get_product_detail

根据商品 ID 获取商品详情。

### compare_products

接收商品 ID 数组，生成商品对比结果。

### add_to_cart

根据商品 ID 和数量加入购物车。

### get_cart

获取当前用户购物车。

# ⑲ 安全与配置

API Key 必须只放在 Node.js 后端。

推荐：

``` text
.env
```

例如：

``` env
LLM_API_KEY=xxxx
LLM_BASE_URL=xxxx
EMBEDDING_API_KEY=xxxx
DATABASE_URL=xxxx
QDRANT_URL=xxxx
```

React 前端禁止直接暴露模型 API Key。

同时：

``` text
.env
```

必须加入：

``` text
.gitignore
```

不要将 API Key 提交到 GitHub。

如果 API Key 曾经出现在截图、公开文档或 Git
仓库中，应立即撤销并重新生成。
